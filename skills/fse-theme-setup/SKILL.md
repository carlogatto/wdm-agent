# FSE Theme Setup — wdm-theme → new client project

**MANDATORY first steps, in order:**
1. Read `${CLAUDE_PLUGIN_ROOT}/shared/fse-foundations.md` — §0 (guard), §2 (structure), §7
   (telaio: menu `ref`, front page, permalinks, `WP_DEVELOPMENT_MODE`), §8 (WP-CLI), §11
   (DESIGN.md format: this skill creates it).
2. Read `{site-root}/DESIGN.md → ## Project Config` **if it exists** — the guard of Step 0
   (`theme_family`: a value other than `fse` = wdm-starter project → stop) comes before anything
   else; this skill is the one that creates the row when DESIGN.md does not exist yet.
3. Read `${CLAUDE_PLUGIN_ROOT}/skills/fse-menu-build/SKILL.md` — the `wp_navigation` is created here with
   its script.

All paths are absolute; `{site-root}` = the conversation's working directory (`pwd`),
`{theme-root}` = `{site-root}/wp-content/themes/{slug}` after the rename.

The deterministic rename is `scripts/setup.sh` (Phase 3): never run those `sed`/`mv` by hand.
Start immediately with Step 0 — no extra trigger phrase required.

## Step 0 — Guard and information

**Guard.** `{site-root}/DESIGN.md`:
- exists with `theme_family` ≠ `fse`, **or without the row** (every wdm-starter project predates
  it) → **STOP**: this is a wdm-starter project, the skill is `new-project-setup`;
- exists with `theme_family: fse` and `wp-content/themes/wdm-theme` is gone → the setup already
  ran: offer only the verification of Phase 5, never a second `setup.sh`;
- does not exist, or exists as the copy shipped by the wdm-theme repo (its `{prefix}` is
  `wdm`) → proceed: the skill creates/rewrites `## Project Config`.

**Anti-scaffold.** `{site-root}/wp-content/themes/wdm-theme/` must exist (clone or ZIP of the
wdm-theme repo). Missing → stop: the skill renames the starter, it does not create a theme.

**Ask the dev for every value before doing anything** (do not proceed until confirmed):

1. **Project slug** — kebab-case (e.g. `pincopallino`): MAMP folder, local URL, DB name, theme
   folder, text domain default.
2. **Prefix** — lowercase, alphanumeric, not `wdm` (e.g. `abc`): replaces `wdm` in block names
   (`abc/hero`), folders (`abc-block-hero`), functions (`abc_`), classes (`abc-header`),
   categories.
3. **Text domain** — default `{slug}`.
4. **Project title** — human name (e.g. `Pinco Pallino`): Theme Name, block/pattern category
   title, kit/footer texts (replaces "WDM Theme").
5. **Local URL** — default `https://{slug}.local:8890/`.
6. **Site title, dev admin username + email** for `wp core install`; **agent admin username**
   (default `{prefix}adminclaude`). Passwords are generated by the agent and shown **once**.

Derived: DB `{slug}-db` (root/root on MAMP), `{db-socket}` = `/Applications/MAMP/tmp/mysql/mysql.sock`,
MAMP PHP = newest `/Applications/MAMP/bin/php/php8*/bin/php`, `{wp-cli}` =
`{mamp-php} -d memory_limit=512M -d mysqli.default_socket={db-socket} {site-root}/wp-cli.phar --path={site-root}`
(absolute phar path: the skills `cd` into `{theme-root}` for npm and the Bash cwd persists)
(fse-foundations §8). Put `{wp-cli}` in a script file in the scratchpad for the session (zsh
does not expand a command stored in a string variable).

## Phase 1 — Environment

### Step 1a — MAMP host and folder `[MANUAL]`
> Prima di procedere, verifica:
> - **MAMP PRO**: server `{slug}.local`, document root `{site-root}/`, PHP 8.x, server avviato.
> - **Cartella** `{site-root}/`: contenuto del repo **wdm-theme** (`CLAUDE.md`, `README.md`,
>   `.gitignore`, `docs/`, `wp-content/themes/wdm-theme/`). I file core di WordPress li scarico io
>   se mancano.
>
> (Il repository git lo creerai tu con Sourcetree alla fine — Step 5b.)
> Quando tutto è pronto scrivi: **confermato**

### Step 1b — Database `[MANUAL]`
> In MAMP PRO crea il database **`{slug}-db`**, collation `utf8mb4_unicode_ci`.
> Quando hai finito scrivi: **fatto**

## Phase 2 — WordPress

### Step 2a — wp-cli.phar + core `[AGENT]`
```bash
cd {site-root}
[ -f wp-cli.phar ] || curl -sSLo wp-cli.phar https://raw.githubusercontent.com/wp-cli/builds/gh-pages/phar/wp-cli.phar
[ -d wp-includes ] || {wp-cli} core download --locale=it_IT --skip-content   # no default themes/plugins
```
`wp-cli.phar` is gitignored by the repo whitelist (verify the line exists).

### Step 2b — wp-config.php `[AGENT]`
Fetch the WordPress secret keys, then write `{site-root}/wp-config.php` from the template
below, substituting `{slug}-db` (database name), `{prefix}_` (table prefix) and the 8 `define()`
lines from the curl output in place of `{SALT_KEYS_FROM_CURL}`:
```bash
curl -s https://api.wordpress.org/secret-key/1.1/salt/
```
```php
<?php
/** Il nome del database di WordPress */
define( 'DB_NAME', '{slug}-db' );

/** Nome utente del database */
define( 'DB_USER', 'root' );

/** Password del database */
define( 'DB_PASSWORD', 'root' );

/** Hostname del database */
define( 'DB_HOST', 'localhost' );

/** Charset del database da utilizzare nella creazione delle tabelle. */
define( 'DB_CHARSET', 'utf8' );

/** Il tipo di collazione del database.*/
define( 'DB_COLLATE', '' );

/** Chiavi univoche di autenticazione e di sicurezza. **/
{SALT_KEYS_FROM_CURL}

/** Prefisso tabella del database WordPress. **/
$table_prefix = '{prefix}_';

/** Modalità di debug di WordPress. **/
define( 'WP_DEBUG', true );
define( 'WP_DEBUG_DISPLAY', false );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEVELOPMENT_MODE', 'theme' ); // niente cache di theme.json e pattern durante lo sviluppo

define( 'WP_MEMORY_LIMIT', '1024M' );

define( 'AUTOMATIC_UPDATER_DISABLED', true );

/** Path assoluto alla directory di WordPress. */
if ( ! defined( 'ABSPATH' ) ) {
  define( 'ABSPATH', __DIR__ . '/' );
}

/** Imposta le variabili di WordPress ed include i file. */
require_once ABSPATH . 'wp-settings.php';
```
Without `WP_DEVELOPMENT_MODE` WP caches the pattern list and theme.json: patterns added later
do not appear. Never overwrite an existing `wp-config.php`: read and complete it.

### Step 2c — Install + agent user `[AGENT]`
```bash
DEV_PASS="$(openssl rand -base64 18)"; AGENT_PASS="$(openssl rand -base64 18)"
{wp-cli} core install --url={local-url} --title="{site-title}" --admin_user={dev-admin} --admin_email={dev-email} --admin_password="$DEV_PASS" --skip-email
{wp-cli} option update siteurl {local-url-without-trailing-slash} && {wp-cli} option update home {local-url-without-trailing-slash}   # wp-cli may append the path
{wp-cli} user create {agent-admin-user} {agent-admin-user}@{slug}.local --role=administrator --user_pass="$AGENT_PASS"
echo "password {dev-admin}: $DEV_PASS — password {agent-admin-user}: $AGENT_PASS"   # read it and report it to the dev, once
```
Run the three lines in the **same** Bash call (variables do not survive between calls). Tell the
dev both passwords **once** in chat; write the agent username (never a password) in
`DESIGN.md → Project Config → {agent-admin-user}`. The dev changes the passwords as they like.

## Phase 3 — Rename and build `[AGENT]`

### Step 3a — setup.sh (once)
```bash
bash ${CLAUDE_PLUGIN_ROOT}/skills/fse-theme-setup/scripts/setup.sh \
  --prefix "{prefix}" --slug "{slug}" --textdomain "{text-domain}" --category "{project-title}" \
  --local-url "{local-url}" --target "{site-root}"
```
It renames the theme folder; replaces `wdm-theme` → text domain, `WDM Theme` → title, `wdm-` /
`wdm_` / `wdm/` / `"wdm"` → prefix (block names, parent/context, theme.json `styles.blocks`,
pattern slugs and `Categories`, BEM classes of parts and kit, handles like `{prefix}-swiper`);
renames `blocks/{prefix}-block-*`, kit and pattern files; sets `build.js` proxy; fixes the
site-root `.gitignore` and `DESIGN.md` residuals; removes generated files (`build/`, `html/`,
compiled css/js — rebuilt in 3b); downloads `wp-cli.phar` if missing; exits 1 on any `wdm`/`WDM`
residual (resolve by hand, then re-check with the same grep). `CLAUDE.md` is not touched
(placeholders resolved from DESIGN.md).

### Step 3b — Dependencies and build
```bash
cd {theme-root} && npm install && npm run build
```
Exit 0; `blocks/*/build/index.asset.php` for every block, `html/{prefix}-home.html`,
`assets/css/main.css`.

## Phase 4 — Activation and site data `[AGENT]`

### Step 4a — Activate
`{wp-cli} theme activate {slug}` → `{wp-cli} theme list --status=active`.

### Step 4b — wp_navigation + ref, before the first render
The parts ship with `"ref":N` of the starter DB: on this site that id is a page or nothing (core
does not check the post type → a page's content inside the menu). Write the minimal plan and
apply it (creates "Menu principale" with the Home link and writes the new `ref` in **both**
`parts/header.html` and `parts/footer.html`):
```bash
cat > {scratchpad}/nav-plan.json <<'EOF'
{ "menus": [ { "title": "Menu principale", "parts": [ "header", "footer" ], "items": [ { "label": "Home", "home": true } ] } ] }
EOF
{wp-cli} eval-file ${CLAUDE_PLUGIN_ROOT}/skills/fse-menu-build/scripts/wp-navigation.php apply {scratchpad}/nav-plan.json
{wp-cli} eval-file ${CLAUDE_PLUGIN_ROOT}/skills/fse-menu-build/scripts/wp-navigation.php dump   # parts.header == parts.footer == new id
```
`fse-menu-build` realigns it from the kit once the pages exist.

### Step 4c — Home, front page, permalinks
```bash
HOME_ID=$({wp-cli} post create --post_type=page --post_title="Home" --post_name=home --post_status=publish --porcelain)
{wp-cli} option update show_on_front page && {wp-cli} option update page_on_front $HOME_ID
{wp-cli} option update permalink_structure '/%postname%/' && {wp-cli} rewrite flush --hard   # writes .htaccess (outside the repo); if it cannot, write the standard WP .htaccess
```
No `front-page.html` (fse-foundations §7): the static Home uses `page.html`.

### Step 4d — Tokens
```bash
node ${CLAUDE_PLUGIN_ROOT}/shared/scripts/sync-theme-json-tokens.js {theme-root}   # DESIGN.md → Design Tokens + assets/css/wp-global-styles.css via {wp-cli}
node ${CLAUDE_PLUGIN_ROOT}/shared/scripts/sync-theme-json-tokens.js {theme-root} --check   # exit 0
cd {theme-root} && npm run build   # html/ with the regenerated global styles
```

### Step 4e — Checks
- `curl -sk -o /dev/null -w '%{http_code}' {local-url}` → 200; page source without `Fatal|Warning`.
- Login as `{agent-admin-user}` (Playwright) → `wp-admin/site-editor.php` 200, templates and
  parts open without invalid blocks; the Home shows header/footer with the menu.
- `{wp-cli} eval 'foreach (WP_Block_Type_Registry::get_instance()->get_all_registered() as $n => $b) if (str_starts_with($n, "{prefix}/")) echo $n, "\n";'`
  → every `blocks/*/block.json` of the repo with the new prefix; patterns `{prefix}/contacts`, `{prefix}/cta`
  (`_register_theme_block_patterns()` first).
- `{wp-cli} post list --post_type=wp_template --format=count` and `wp_template_part` → 0 (files
  are the source).
- `{site-root}/wp-content/debug.log` empty (or absent).

### Step 4f — Formidable (`{prefix}/form` and the default form part)
```bash
{wp-cli} plugin install formidable --activate && {wp-cli} language plugin install formidable it_IT
{wp-cli} eval 'FrmAppController::install();'   # WP-CLI does not create the tables otherwise
{wp-cli} eval '$s = FrmAppHelper::get_settings(); $s->load_style = "none"; $s->store();'   # the theme styles the form
```
`parts/form-contacts.html` ships with the starter's `formId` (a form of the starter DB): set it
to `0` (title and text only, no broken form) and add to `## Domande aperte`: "form di default:
creare il form Contatti in Formidable e impostare `formId` nella part (Aspetto → Editor →
Parti)".

## Phase 5 — Handover

### Step 5a — DESIGN.md and CLAUDE.md `[AGENT]`
- `## Telaio`: header, footer, templates, form di default `implementato` (inherited from the starter; the project
  kit will redesign them with `fse-kit`).
- `## Pagine`: Home `/` `da progettare` (the WP page exists, empty; its kit is the project's;
  `fse-brief` rewrites these rows from the map);
  Catalogo blocchi `/catalogo-blocchi/` `kit` (`src/kit/{prefix}-blocks.kit`, every variant of the
  shipped blocks: the regression page, built by the first `fse-build`). The starter's demo page
  kits (`{prefix}-servizi.kit`, `{prefix}-contatti.kit`) get no row; wdm-theme's "fuori dal
  flusso" note and its `## Log decisioni` rows are dropped.
- `## Blocchi`: one row per `blocks/*/build/index.asset.php` on disk, `implementato`, origin
  "starter" (variants and children from each README).
- `## Navigazione`: "Menu principale" id, parts header+footer, items: Home.
- `## Domande aperte`, `## Log decisioni` (one row: setup date, values).
- `CLAUDE.md` ships with the repo and resolves `{prefix}`/paths from DESIGN.md: verify its
  "First: read DESIGN.md" protocol and routing table mention only `fse-*` skills.

### Step 5b — Dev check and git `[MANUAL]`
> Il setup è completo. Controlla nel browser `{local-url}` (home con header/footer e menu) e
> `wp-admin` con il tuo utente. Poi con Sourcetree: repository locale in `{site-root}/`, remoto,
> commit iniziale e push. Ricorda di cambiare le due password che ti ho mostrato.
> Quando hai finito scrivi: **fatto**

Remind the dev: `style.css` header (Theme Name/Description/Author), `screenshot.png`,
`assets/img/` placeholders, `SETUP.md` can be deleted once the repo is created. Next session:
`fse-brief` (the designer deposits the brief in `{site-root}/docs/brief/`), then `fse-kit`.

## What is NOT automated
MAMP host and DB (GUI) · git (Sourcetree) · the dev's browser check · password changes.

## Never
Run `setup.sh` twice · touch the starter repo · persist a password (chat only, once) · git
commands · write `CLAUDE.md` by hand (it ships with the repo).
